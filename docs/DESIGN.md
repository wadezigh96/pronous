# PRONOUS Design System

PRONOUS uses a compact terminal-style interface inspired by professional on-chain dashboards.

## Visual language

- Dark neutral background
- Gold as the primary action/accent
- Thin borders and compact cards
- IBM Plex Mono for data and system labels
- Inter for product text
- Dense information hierarchy
- Minimal decoration
- Responsive layout for mobile

## Product principles

### 1. Utility first
Every screen element should answer a practical question: what is the asset, what is the gap, what is the market state, and what can happen next?

### 2. State is visible
Prefer explicit states such as:

`LIVE` · `DEMO` · `OBSERVING` · `GUARDED` · `BLOCKED` · `READY`

### 3. Explain before execute
A signal should expose its inputs before an execution path becomes available.

### 4. No fake activity
Demo data is clearly labeled. Unverified transaction capabilities stay gated.

## Main surfaces

- **Overview** — system status and key market metrics.
- **Market** — tokenized-stock universe.
- **Asset Detail** — token/reference prices, spread and market state.
- **Divergence Radar** — largest observed gaps.
- **Agent Skills** — capabilities and guardrails.
- **Execution Cockpit** — preflight and confirmation boundary.
- **Ask PRONOUS** — simple market explanation layer.
